Installation

Download the latest build from the Releases page:

PlatformFile
Windows (x64)cloudbridge-windows-x64.exe
macOS (Apple Silicon)cloudbridge-macos-arm64.dmg
Windows: SmartScreen may warn about unsigned executables. Click "More info" → "Run anyway" to proceed.
macOS: Open the .dmg and drag CloudBridge to Applications. The app is ad-hoc signed but not notarized, so the first launch is blocked with "Apple could not verify CloudBridge is free of malware". Double-click the app, click Done, then open System Settings → Privacy & Security, scroll to Security, and click Open Anyway — the button appears only after a blocked attempt and expires after about an hour. From a terminal, xattr -d com.apple.quarantine /Applications/CloudBridge.app does the same thing in one step.
On macOS 15 (Sequoia) and later, Control-click → Open no longer works. Apple removed that bypass for unnotarized apps, which is why the warning offers only Done and Move to Trash. Use System Settings or the terminal command above. On macOS 14 and earlier, Control-click → Open is still the quickest route.

Linux and Intel Macs are not published as binaries; both build from source. You need Rust 1.75+, and on Windows the fxc.exe shader compiler from the Windows SDK in your PATH:

git clone https://github.com/JetSquirrel/cloudbridge.git
cd cloudbridge
cargo run --release

Configuration

A source reaches the ledger through a billing API, through the bill export its console produces, or both. Only the first kind needs credentials; for the rest, add the account and go straight to Bill file import.

AWS

  1. Create an IAM user with Cost Explorer access.
  2. Attach the policy below (also in docs/policies.md).
  3. Generate an Access Key ID and Secret Access Key.
  4. Add the account in CloudBridge.
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": [
                "ce:GetCostAndUsage",
                "ce:GetCostForecast",
                "ce:GetDimensionValues",
                "ce:GetTags"
            ],
            "Resource": "*"
        }
    ]
}

AWS Cost Explorer charges $0.01 per request. CloudBridge keeps this near zero: a billing period is re-fetched at most once a day by default, and one request per period carries everything — the current and previous period, so roughly $0.02 a day.

Alibaba Cloud

  1. Open the RAM console and create a RAM user for API access.
  2. Attach the built-in AliyunBSSReadOnlyAccess system policy.
  3. Create an AccessKey for the user.
  4. Add the account in CloudBridge.

The Alibaba Cloud billing API is free of charge.

DeepSeek

  1. Open platform.deepseek.com and create an API key.
  2. Add the account in CloudBridge using that key.

DeepSeek's API reports a balance (granted and topped-up), not cost — it says how much is left, never what the money went on. For that, import its usage download as well; see Bill file import. The balance API is free of charge.

Volcengine, OpenAI and Anthropic

These three are read from a file and sign nothing, so they ask for no credentials: add the account with a name and nothing else, then import the export. Their billing APIs are planned — each already names the credential it will want (OpenAI and Anthropic need an organization or admin key, not an ordinary project key) — but nothing is stored in your keyring until there is something to use it for.

Bill file import

A bill export downloaded from a provider's console parses into the same ledger rows a fetch produces. Downstream — totals, charts, alerts, attribution — an imported month is indistinguishable from a fetched one. It is often the finer reading: Alibaba Cloud's billing API reports Model Studio (百炼) as one figure a month, while its export reports it per model, with token counts as a real pricing unit.

SourceWhere the export comes fromWhat it adds
Alibaba CloudExpenses and Costs → Bill Details → ExportModel Studio (百炼) per model; instance-level detail for everything else
VolcengineBilling → Bill Details → ExportArk (火山方舟) per endpoint and token type
OpenAIUsage → ExportCost or token usage, per project and model
Anthropic (Claude)Usage or Cost → ExportCost or token usage, per workspace and model
DeepSeekUsage → DownloadPer-day, per-model spend — its API reports only a balance

Importing

  1. Download the export from the provider's console.
  2. Go to Accounts and click Import bill on the account's row.
  3. Pick the file. CloudBridge reports how many charges it wrote and which months it replaced.
An import replaces every month the file covers. The export is the provider's own bill, so it supersedes whatever the billing API reported for that month rather than being added to it. The corollary: a file narrowed to a single product in the console replaces that whole month with that one product — export the full bill unless that is what you mean. Re-importing a corrected export of the same month is safe.
An imported month is never replaced by an automatic fetch, Force Refresh included. "Force" means "do not trust the freshness window", not "discard what I imported". To update an imported month, import a corrected export of it.

DeepSeek's zip

DeepSeek's console hands out a zip of two CSVs. Import it exactly as it downloaded: CloudBridge reads the cost-*.csv inside and leaves amount-*.csv alone, because that file's amount column is a token count — read as money, a day of 10,787 cached input tokens would book as ¥10,787.

Usage exports carry no money

A usage export has token counts and no amounts. Those rows land with no billed cost and a cost basis of absent: pricing them at list would put a number in the ledger that nobody was charged. A cost export keeps a quantity only where exactly one token column is filled in, since input and output tokens are priced differently and their sum is not what the amount was charged for.

If the import refuses the file

  • "not UTF-8 text" — both Chinese consoles can produce a GBK export. Re-save it as UTF-8; decoding on a guess would mangle every product name in the bill.
  • A column that matches nothing — none of these exports is a documented file format, so columns are matched through alias lists covering the Chinese console, the English console and each provider's API field names. The error names the columns your file actually has; open an issue with that list.

Usage

Adding an account

  1. Go to Accounts in the sidebar.
  2. Pick the source and enter a name, plus credentials if it has a billing API. Volcengine, OpenAI and Anthropic ask for none.
  3. Click Save.

Reading the Overview

The header carries a range control — MTD, 30d or 12m — and every number on the page is computed for the window you pick.

  • The headline spend is net of credits: what you were actually charged. The gross usage and the credits that took it down are shown beside it.
  • The chart, the change percent, Where it went and the biggest movers all run on gross usage. An account whose usage is fully covered by credits nets to about zero, and a trend drawn on that base is noise rather than information.
  • The Unallocated figure is the share of usage that reaches no business line — the part of the bill you cannot yet explain.

Hovering a trend chart snaps to the nearest point and draws a guide line, a dot, and a tooltip with that bucket's date and amount.

One account at a time

Click an account's name on the Accounts page to drill into it: the same range control, a net / gross / credits stat row, that one account's daily or monthly usage trend, and a per-service table giving each service's share of the window and its change against the comparison window.

A balance-only source such as DeepSeek has no API-reported usage — its service rows arrive through bill file import, so the page stays empty until you import one.

Attribution

The Attribution page draws the month as a Sankey: source, then service or model, then business line, with an explicit Unallocated node. Flows are gross usage — a net flow can be negative, which means nothing in a Sankey. A charge is assigned to a line by its business_line tag; without one it lands in Unallocated.

Choosing a reporting currency

Go to Settings → Reporting and pick the currency totals are shown in. Charges keep the currency they were billed in — only the view they are read through changes, so switching back and forth costs nothing. A charge no rate covers is reported, never counted at par.

Refreshing

A billing period is re-fetched at most once a day by default; Settings → Refreshing offers 6, 12, 24 or 48 hours. Refresh picks up anything stale; Force Refresh re-fetches regardless, at the cost of another paid API call. A month that arrived by import is never replaced by a fetch, Force Refresh included.

Demo data

Settings → Demo data loads three accounts and twelve months of realistically-shaped fake ledger, so you can see what the app looks like with a bill in it before connecting anything. Demo rows are keyed under a demo- prefix, carry no credentials, and are skipped by refresh, so none of them ever reaches a provider API. Clearing removes every one of them.

Alerts & rules

Rules are evaluated against the ledger when you open the app and when the Alerts page loads — a desktop app cannot watch your spend while it is closed, and CloudBridge does not pretend otherwise. Three rules ship enabled, and each can be tuned or disabled on the Rules page.

RuleFires whenDefault
Model cost growth anomalyA (source, service) pair's daily spend runs far above its own 7-day trailing baseline, for several days running2.5× for 2 consecutive days
Balance floorA prepaid balance falls below the floor — the account's monthly budget, where it has one200, in the account's own currency
Untagged spend ratioToo much of the month's usage reaches no business lineAbove 15%

An alert names what it saw, not just that something happened: the day's figure, the baseline it broke, how long the streak has held, and what the month ends at if it does. Each one can be resolved, snoozed or dismissed; a condition that stops holding is resolved for you the next time the page loads.

Data Storage

Everything lives on your machine:

PlatformLocation
Windows%APPDATA%\CloudBridge\data\
macOS~/Library/Application Support/CloudBridge/
Linux~/.local/share/CloudBridge/
  • billing.duckdb — the ledger: every charge, in the currency it was billed in
  • cloudbridge.duckdb — accounts and settings
  • raw/ — provider responses as fetched and bill files as imported, partitioned by source, account, and billing period, so a mapping fix replays from the copy CloudBridge kept instead of paying for another fetch
  • config.json — application configuration

Credentials are not in any of these files. They live in the OS keyring.

Security

  • Credentials live in your OS keyring (Windows Credential Manager, macOS Keychain, Linux Secret Service) — never in the database.
  • No data is transmitted except direct API calls to your cloud providers.
  • Raw billing payloads are written to a local directory and nowhere else.
  • The executable contains no embedded credentials.
